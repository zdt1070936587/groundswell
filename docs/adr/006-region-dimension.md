# ADR-006 region 维度从第一天进入主键

## 背景

结果需要按大中华区、东南亚、北美、拉美、欧洲区分，并且要能做跨区信息差与扩散路径分析。事后给大表补维度代价极高。

## 决策

- 区域是维度，不是分叉：一条流水线，所有统计表主键带 `region`；每小时另写一行 `region='GLOBAL'` 汇总。
- `configs/regions.yaml` 维护 区域 → 国家（ISO 3166）→ 语言 / 时区 / 别名 / 本地化上下文，边界调整只改配置。
- 四级归属：源级 → 子频道（subreddit、geo、国家榜）→ 内容级（国家别名 + 语言弱证据）→ GLOBAL 兜底；记录 `region_method` 与 `region_confidence`。
- 一条条目可以有多个区域权重（`item_regions`），统计时按权重累加。
- 时间统一存 UTC，日报按区域时区切“天”。
- 商机按 (话题, 区域) 分别生成，prompt 注入该区域的渠道、支付、监管上下文。

## 后果

- 新增区域 = 新增配置与数据源，不动核心代码。
- 低密度区域容易出现小基数误报，统一用最小样本阈值与 Poisson 标准差下限抑制。
